# SPEED ONLINE

トランプの「スピード(Speed)」を、友達と部屋コードでつないでリアルタイム対戦できるWebアプリです。

- アカウント登録・ログイン(ユーザー名 + パスワード)
- 部屋を作成 → 5桁の部屋コードを友達に共有 → 相手が入室 → 対戦開始
- サーバー側でルール判定を行う本格対戦(手札の中身は相手に見えません)
- 勝敗の記録(通算 勝ち/負け)

## 動作環境

- Node.js 18以上推奨

## データベースについて(重要)

アカウント情報(ユーザー名・パスワード・勝敗数)は **Postgres** に保存します(`pg` パッケージ使用)。無料で使える [Supabase](https://supabase.com) のPostgresを使う想定です。

> 以前のバージョンではローカルの `data.sqlite` ファイルを使っていましたが、RenderのようなPaaSの無料プランはファイルシステムが一時的なもので、再デプロイ・再起動のたびにファイルが消えてしまいます。そのため外部のPostgresに保存する方式に変更しました。

### Supabaseプロジェクトの作り方

1. [supabase.com](https://supabase.com) にGitHubアカウントでサインアップし、New Project を作成(無料プランでOK)。
2. プロジェクト作成時に設定するデータベースパスワードを控えておく。
3. 左メニュー **Project Settings → Database → Connection string** を開き、**URI** 形式の接続文字列をコピーする(`postgresql://postgres:...` のような文字列)。パスワード部分は先ほど控えたものに置き換える。
4. これを `.env` の `DATABASE_URL` に設定する(ローカル用)。Renderにデプロイする場合はRenderの環境変数にも同じ値を設定する(下記参照)。

Supabaseの無料プランは1週間アクセスがないと自動で一時停止しますが、次にアクセスがあれば自動的に再開し、データは消えません(友達内で遊ぶ程度の用途なら問題ありません)。

## セットアップ(ローカル)

```bash
cd speed-online
npm install
cp .env.example .env   # JWT_SECRETとDATABASE_URLを自分の値に書き換える
npm start
```

起動したら `http://localhost:3000` を開いてください。友達と対戦する場合は、同じネットワーク内であれば `http://<あなたのPCのIP>:3000` を、外部からも遊べるようにするにはあとで説明するデプロイを行ってください。

開発中に自動リロードしたい場合は `npm run dev`(Node標準の `--watch` を使用)。

## 遊び方

1. 新規登録してログインします。
2. ロビー画面で「部屋を作成」を押すと5桁の部屋コードが発行されます。それを友達に伝えてください。
3. 友達は「部屋に入る」からコードを入力して入室します。
4. 2人揃うと部屋を作った側(ホスト)に「対戦開始」ボタンが表示されるので押すと対戦スタートです。
5. 手札のカードをクリックすると、出せる山(数字が1つ違う、またはK⇄Aのループ)に自動で出ます。両方の山に出せる場合はどちらの山をクリックするか選べます。
6. 出せるカードがなくなったら「出せるカードがない」を押してください。相手も同時に手詰まりになると、両者の山札からカードが1枚ずつ場に追加されます(スピット)。
7. 手札と山札をすべて出し切った方が勝ちです。

### 採用しているハウスルール

スピードは地域や家庭によって細かいルールが違うゲームなので、このアプリでは次のルールを採用しています(`gameEngine.js` の冒頭コメントにも記載):

- 52枚(ジョーカーなし)。各プレイヤーに手札5枚+場の初期カード1枚+山札20枚(合計26枚)を配布。
- 数字のつながりは A-2-3-...-K に加えて、K と A も隣接扱い(ループ)。
- カードを出すと、山札から1枚自動的に手札に補充されます(手札が常に5枚になるよう)。
- 両者が同時に「出せるカードがない」状態になると、各自の山札の一番上のカードがそれぞれの場に追加されます。
- どちらの山札も追加できない場合はそこで終了し、残りカード枚数が少ない方の勝ち(同数なら引き分け)。

## 技術構成

- **バックエンド**: Node.js + Express + Socket.io(リアルタイム通信)+ better-sqlite3(アカウント永続化)+ JWT認証
- **フロントエンド**: 素のHTML/CSS/JavaScript(ビルド不要)
- **ゲームロジック**: `gameEngine.js` にサーバー権威の判定ロジックを分離。クライアントは見た目の補助表示のみ行い、最終判定は必ずサーバー側で行うため不正なカードプレイはできません。

## ファイル構成

```

│       ├── api.js      # fetch/ソケットの共通ヘルパー
│       ├── auth.js
│       ├── lobby.js
│       └── game.js
└── data.sqlite         # 初回起動時に自動生成されるアカウントDB
```

## Renderへのデプロイ手順

1. [render.com](https://render.com) にGitHubアカウントでサインアップする。
2. ダッシュボードで **New +** → **Web Service** を選び、このプロジェクトのGitHubリポジトリを連携する。
3. 設定項目は以下の通り:
   - **Language / Runtime**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free でOK(友達内で遊ぶ用途なら十分)
4. **Environment** タブ(または作成画面の Advanced → Environment Variables)で、以下を追加する:
   - `JWT_SECRET` … ランダムな長い文字列(例: パスワード生成ツールで作った32文字程度の文字列)
   - `DATABASE_URL` … 上記で取得したSupabaseの接続文字列
   - `PORT` は設定不要(Renderが自動で割り当てて渡してくれます)
5. **Create Web Service** を押すとビルド・起動が始まり、`https://<サービス名>.onrender.com` のようなURLが発行されます。このURLを友達に共有すれば、外部からもアクセスして対戦できます。

### 注意点

- Render無料プランはWeb Serviceがスリープするため、15分ほどアクセスがないと次のアクセス時に起動まで数十秒かかります。友達との対戦前に一度アクセスして起こしておくとスムーズです。
- Supabase無料プランも1週間アクセスがないとデータベースが一時停止しますが、次のアクセスで自動的に再開します。
- コードを修正してGitHubにpushすると、Renderは自動で再ビルド・再デプロイします(Auto-Deploy設定がオンの場合)。

## 既知の制約

- 現在は2人対戦のみ対応です。
- 観戦機能や複数部屋の一覧表示はありません。
- 通算成績はログイン中のアカウントに保存されますが、パスワードリセット機能はありません。
