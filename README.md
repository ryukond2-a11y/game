# SPEED ONLINE

トランプの「スピード(Speed)」を、友達と部屋コードでつないでリアルタイム対戦できるWebアプリです。

- アカウント登録・ログイン(ユーザー名 + パスワード)
- 部屋を作成 → 5桁の部屋コードを友達に共有 → 相手が入室 → 対戦開始
- サーバー側でルール判定を行う本格対戦(手札の中身は相手に見えません)
- 勝敗の記録(通算 勝ち/負け)

## 動作環境

- Node.js 18以上推奨

## セットアップ

```bash
cd speed-online
npm install
cp .env.example .env   # 必要ならJWT_SECRETを好きな文字列に変更
npm start
```

起動したら `http://localhost:3000` を開いてください。友達と対戦する場合は、同じネットワーク内であれば `http://<あなたのPCのIP>:3000` を、外部からも遊べるようにするにはあとで説明するデプロイを行ってください。

開発中に自動リロードしたい場合は `npm run dev`(Node標準の `--watch` を使用)。

## 遊び方

1. 新規登録してログインします。
2. ロビー画面で「部屋を作成」を押すと5桁の部屋コードが発行されます。それを友達に伝えてください。
3. 友達は「部屋に入る」からコードを入力して入室します。
4. 2人揃うと部屋を作った側(ホスト)に「対戦開始」ボタンが表示されるので押すと対戦スタートです。
5. 手札のカードをクリックすると、出せる山(数字が1つ違う、またはK⇄Aのループ)に自動で出ます。両方の山に出せる場合はどちらの山をクリックするか選べます。
6. 出せるカードがなくなったら「出せるカードがない」を押してください。相手も同時に手詰まりになると、両者の山札からカードが1枚ずつ場に追加されます(スピット)。
7. 手札と山札をすべて出し切った方が勝ちです。

### 採用しているハウスルール

スピードは地域や家庭によって細かいルールが違うゲームなので、このアプリでは次のルールを採用しています(`gameEngine.js` の冒頭コメントにも記載):

- 52枚(ジョーカーなし)。各プレイヤーに手札5枚+場の初期カード1枚+山札20枚(合計26枚)を配布。
- 数字のつながりは A-2-3-...-K に加えて、K と A も隣接扱い(ループ)。
- カードを出すと、山札から1枚自動的に手札に補充されます(手札が常に5枚になるよう)。
- 両者が同時に「出せるカードがない」状態になると、各自の山札の一番上のカードがそれぞれの場に追加されます。
- どちらの山札も追加できない場合はそこで終了し、残りカード枚数が少ない方の勝ち(同数なら引き分け)。

## 技術構成

- **バックエンド**: Node.js + Express + Socket.io(リアルタイム通信)+ better-sqlite3(アカウント永続化)+ JWT認証
- **フロントエンド**: 素のHTML/CSS/JavaScript(ビルド不要)
- **ゲームロジック**: `gameEngine.js` にサーバー権威の判定ロジックを分離。クライアントは見た目の補助表示のみ行い、最終判定は必ずサーバー側で行うため不正なカードプレイはできません。

## ファイル構成

```
speed-online/
├── server.js         # Express + Socket.io サーバー、認証API、部屋/対戦の管理
├── gameEngine.js      # スピードのルール判定(配札・出せる手の判定・スピット処理)
├── db.js              # SQLiteのユーザーテーブル定義
├── public/
│   ├── index.html     # ログイン/新規登録
│   ├── lobby.html      # 部屋の作成・入室
│   ├── game.html        # 対戦画面
│   ├── css/style.css
│   └── js/
│       ├── api.js      # fetch/ソケットの共通ヘルパー
│       ├── auth.js
│       ├── lobby.js
│       └── game.js
└── data.sqlite         # 初回起動時に自動生成されるアカウントDB
```

## 友達と外部から対戦するには(デプロイ)

ローカルで動かすだけだと同じPC/同じネットワーク内でしか遊べません。外部の友達と遊ぶ場合は、Render・Railway・Fly.ioなどNode.jsアプリをホスティングできるサービスにデプロイし、発行されたURLをブラウザで開いてもらう形になります。おおまかな手順はどのサービスでも共通です。

1. このプロジェクトをGitHubリポジトリにpushする
2. ホスティングサービスでリポジトリを連携し、ビルドコマンドなし・起動コマンド `npm start` を指定
3. 環境変数 `JWT_SECRET` を設定(ランダムな長い文字列)
4. デプロイ後に発行されるURLを友達に共有

SQLiteはファイルベースのため、デプロイ先によっては再デプロイ時にデータが消える場合があります。長期運用する場合はPostgresなど永続ストレージのあるDBへの切り替えを検討してください。

## 既知の制約

- 現在は2人対戦のみ対応です。
- 観戦機能や複数部屋の一覧表示はありません。
- 通算成績はログイン中のアカウントに保存されますが、パスワードリセット機能はありません。
